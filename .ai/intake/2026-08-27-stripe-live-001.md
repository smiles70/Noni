# Intake — STRIPE-LIVE-001: Production Stripe payment flow and mynaani.com hosting

**Date:** 2026-08-27  
**Requester:** Product  
**Process:** v9.51  
**Scope:** Move the Mynaani payment flow from the mock provider to live Stripe, deploy/host the app on mynaani.com (Cloudflare-managed domain), and retire or redirect the noni-api-production.up.railway.app / noni-frontend references.

---

## Motivation

Mynaani currently runs with `PAYMENT_PROVIDER=mock`. The product is ready for paid B2C and B2B2C pilots, so we need real payment processing. The team owns `mynaani.com` and wants it to be the customer-facing home for the app. Cloudflare manages the domain.

## Requirements

1. **Stripe live mode**
   - Obtain live Stripe keys (`STRIPE_SECRET_KEY`, `STRIPE_PUBLISHABLE_KEY`, `STRIPE_WEBHOOK_SECRET`).
   - Create a live Stripe product and price for `modules_4_5`.
   - Store `STRIPE_PRICE_ID_MODULES_4_5`.
   - Verify `backend/services/payment_provider.py` works in `stripe` mode.
   - Ensure webhook endpoint `POST /api/billing/stripe-webhook` works in production.
   - Verify Celery worker processes `process_stripe_webhook` and `process_event`.
   - Confirm gift-purchase flow works with real Stripe Checkout.

2. **Domain and hosting**
   - Customer-facing app should be served from `mynaani.com`.
   - Use Cloudflare for DNS / CDN / HTTPS.
   - Backend API reachable at `mynaani.com` or `api.mynaani.com`.
   - Update CORS, `FRONTEND_URL`, `STRIPE_SUCCESS_URL`, `STRIPE_CANCEL_URL`.
   - Retire `https://noni-api-production.up.railway.app` references in the production bundle.

3. **Environment and secrets**
   - Add `PAYMENT_PROVIDER=stripe` to live env.
   - Add live Stripe secrets to the deployment target (Railway/legacy-platform/Cloudflare Pages).
   - Add `mynaani.com` to allowed CORS origins.
   - Verify `SESSION_SECRET`, `MAGIC_API_SECRET_KEY`, etc. are production-grade.

4. **Operational readiness**
   - Stripe webhook signature verification must pass.
   - Refund flow should be end-to-end tested in live/test mode.
   - Monitor `billing_event` audit logs.
   - Document the deployment and secrets map.

## Explicit non-goals

- Do not change the B2B2C access-code flow.
- Do not change the product code `modules_4_5` (rename can be a later step).
- No new payment providers (PayPal, etc.).

## Success criteria

- A signed-in learner on `mynaani.com` can buy Modules 3-5 with a real card.
- Gift purchase issues a token and redeems it.
- B2B2C access codes still redeem to the same product.
- Webhook correctly grants entitlements.
- Build artifact has no `noni-api-production.up.railway.app` or `localhost` references.
