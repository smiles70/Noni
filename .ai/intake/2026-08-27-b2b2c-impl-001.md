# Intake — B2B2C-IMPL-001: Implement organization sponsorship and access codes

**Date:** 2026-08-27  
**Requester:** Product  
**Process:** v9.51  
**Scope:** Implement the B2B2C organization-sponsorship capability: organizations purchase bulk seats, Mynaani generates access codes, and learners redeem those codes to unlock Modules 3-5.

---

## Motivation

GTM-001 identified B2B2C as the primary scalable revenue channel for Mynaani. This intake covers the technical implementation of the access-code redemption and org-licensing system so sales can run pilots.

## Requirements

1. **Organizations** can be created and managed by Mynaani staff.
2. **Org licenses** grant a fixed number of seats for a fixed product (Modules 3-5).
3. **Access codes** are generated per license; each code is redeemable once by a learner.
4. **Learners** enter a code at the paywall or a dedicated page to receive an entitlement.
5. **Redemption** is idempotent and logged to the billing audit table.
6. **Admin reporting:** view seats used/remaining per license.
7. **No dark patterns:** code entry is low-pressure, does not auto-charge the learner.
8. **Payment handling:** org checkout can be processed by mock or Stripe, reusing the existing `PaymentProvider` abstraction.

## Boundaries

- Does not include a public org self-signup page.
- Does not include a full admin dashboard; only backend endpoints and a minimal org admin view if feasible.
- Reuses ADR 0021/0022 pricing and entitlement model.
- Must not break existing B2C or gift flows.

## Success criteria

- `POST /api/billing/org/checkout` creates an org license and purchase.
- `POST /api/billing/org/codes` (or generate) creates access codes.
- `POST /api/billing/org/redeem` grants an entitlement.
- `GET /api/billing/org/{org_id}/usage` returns seats used/remaining.
- Frontend paywall supports "I have an organization code" entry.
- Type-check and production build pass.
- Process artifacts: preflight, phase inventory, implementation plan, KG update.
