## What was discovered and fixed

### Issue 1 — Ontology crawler false positive on PDF downloads
- **Symptom:** Crawl reported 2 "navigation errors" on `/whitepapers/*.pdf`.
- **Root cause:** Playwright `page.goto` treats a download start as a navigation error.
- **Fix:** `scripts/agentic-ci/ontology-crawl.mjs` now skips binary extensions (`.pdf`, `.zip`, etc.) when discovering and visiting links.
- **Verification:** Re-run reported 0 HTTP >= 400, navigation, page, or console errors.

### Issue 2 — Security audit false positives from `.venv` and docs examples
- **Symptom:** Secret scan reported 23 findings from Python virtual-env test files and an ops guide with example placeholder secrets.
- **Root cause:** The scanner was traversing `.venv` and `docs/ops`.
- **Fix:** `scripts/agentic-ci/security-audit.mjs` now excludes `.venv/`, `*.pyc`, and `docs/ops/` from secret scanning.

### Issue 3 — Missing security headers on the Vite dev server
- **Symptom:** Security-header check reported missing `X-Content-Type-Options` and `X-Frame-Options`.
- **Root cause:** Two layers:
  1. A stale, ignored `frontend/vite.config.js` (generated by an earlier `tsc -b`) was shadowing `frontend/vite.config.ts`, so Vite loaded the old JS instead of the new TS security-header plugin.
  2. `frontend/tsconfig.node.json` emitted the config back into the source directory on every build.
- **Fix:**
  - Added `securityHeadersPlugin` to `frontend/vite.config.ts`.
  - Set `outDir` in `frontend/tsconfig.node.json` to `node_modules/.vite-config-build` so `tsc -b` no longer emits a shadowing `.js` next to the source config.
  - Removed the stale `frontend/vite.config.js` and `frontend/vite.config.d.ts` from the workspace.
- **Verification:** `curl -sI http://127.0.0.1:5173/` now returns `X-Content-Type-Options: nosniff` and `X-Frame-Options: DENY`.
