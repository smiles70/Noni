Mynaani Stripe Live Setup

Read this if you are the person clicking buttons. This guide uses simple words and tells you exactly which website, button, and box to use. It is split into batches A through F. Do each batch in order. Skip a batch only if someone tells you it is already done.

What “live” means: Real money. A real card. A real Stripe account. Test mode is only for practice. Do the steps below in live mode unless the step says otherwise.
Before you start, gather these things:
  • Login for dashboard.stripe.com
  • Login for railway.com
  • Login for GoDaddy (only if DNS changes are needed)
  • Login for Cloudflare (only if the Pages build needs updating)
  • A clean notepad or password manager to copy secret values

Batch A — Set up the Stripe product and price

Why: Stripe needs to know what you are selling and how much it costs before anyone can pay.

A1. Make sure your Stripe account can take live money

  1. Go to dashboard.stripe.com and sign in.
  2. Look at the top right. If the switch says “Test mode”, click it so it turns gray and says “Live mode”.
  3. Click “Activate your account” or “Account settings” if you see a banner. Add your business bank account, tax info, and business address.
  4. Wait until you do not see a red warning that says payments are disabled. This may take hours or days.
Do not go live until the account is activated. If the banner still says “Payments disabled,” real cards will be rejected.

A2. Create the product

  1. In the left sidebar, click “Products”.
  2. Click the “+ Add product” button near the top right.
  3. In the box called “Product name”, type exactly:
    Mynaani Modules 4-5
  4. In the box called “Description”, type:
    One-time purchase: lifetime access to Modules 4 (Skills) and 5 (Agents).
  5. Click “Save product”.

A3. Create the price for one person buying for themselves

  1. On the product page, click “+ Add price”.
  2. Click “One-time”.
  3. Click the currency dropdown and choose “USD — United States dollar”.
  4. In the “Price” box, type the approved self-purchase price. Example: 39.00 or 49.00. Use the number the team decided.
  5. Click “Save price”.
  6. You will see a new line with a code starting with price_. Click the three dots to the right and choose “Copy price ID”. Paste it in your notepad and label it “Self-purchase price ID”.

A4. Gift price — read this first

Important: Right now the app charges the same price for a gift as for a self-purchase. It only knows about one price ID. Creating a second “gift” price in Stripe will do nothing until an engineer changes the code. Also, the gift flow has a known bug in live mode (the gift code is lost after payment — see Batch F). Decision needed: either launch with one price and no gift option, or wait for the engineering fix before selling gifts. Do not create a second price unless the team has decided to do the code work.
Do not create a subscription. Both prices must be One-time. Mynaani does not use subscriptions.

Batch B — Add live Stripe secrets to Railway

Why: The Mynaani backend needs permission to talk to Stripe. These secret values go into Railway, never into the code.

B1. Get your live secret key

  1. In Stripe, click “Developers” in the left sidebar.
  2. Click “API keys”.
  3. Make sure the page is in Live mode (top right).
  4. Find the row called “Secret key”. Click “Reveal test key” or “Reveal live key” if it is hidden.
  5. Click the copy icon. The key starts with sk_live_. Label it “Stripe secret key”.

B2. Open the right place in Railway

  1. Go to railway.com and sign in.
  2. Find the project called noni (or the project ID 2e666ec8-c007-4054-b763-0d45d30759a2).
  3. Click the service called noni-api (or the service with ID 3f9c0c51-c82d-4d92-b159-09d5f0509c4d).
  4. Click the tab called “Variables” (next to “Deploys” and “Logs”).

B3. Add or change the payment variables

Do NOT set PAYMENT_PROVIDER to stripe yet. If you turn Stripe on before the webhook secret exists (that happens in Batch D), every billing page on the site will crash with an error. Leave PAYMENT_PROVIDER as mock for now. You will flip it in Batch D, step D2.

For each row in the table, click the “+ New Variable” button or find the existing variable and click the pencil icon to change it.

Variable nameWhat to paste or type
PAYMENT_PROVIDERLeave as mock for now (flip to stripe in Batch D)
STRIPE_SECRET_KEYThe sk_live_... key you copied
STRIPE_PRICE_ID_MODULES_4_5The self-purchase price_... you copied
STRIPE_SUCCESS_URLhttps://www.mynaani.com/purchase/success
STRIPE_CANCEL_URLhttps://www.mynaani.com/purchase/cancel

The STRIPE_SUCCESS_URL must not have ?purchase=... on the end. It must be clean, exactly as shown above.
Check your work: All the variables above are saved in Railway. The site still runs in mock mode — that is correct for now. The switch to live happens in Batch D.

Batch C — Make sure the product row exists in the database

Why: The backend looks up a product called modules_4_5 before it can make a checkout.

C1. Run the product seed inside the running service

Railway’s dashboard does not have a shell button. You use the Railway CLI on your computer to open a terminal inside the running container.

  1. On your computer, open a terminal.
  2. Type this and press Enter (it opens a terminal inside the production service):
    railway ssh --project 2e666ec8-c007-4054-b763-0d45d30759a2 --service 3f9c0c51-c82d-4d92-b159-09d5f0509c4d --environment 61bd7eea-6471-4ba2-b3d8-23e1c35f8dc1
  3. When the prompt changes, type this exact command and press Enter:
    python -m scripts.seed_products
  4. Read the output. It should say either “created”, “updated”, or “unchanged” and show the modules_4_5 product.
Check your work: In the same shell, paste this one-line command and press Enter:
python -c "from backend.core.database import SessionLocal; from backend.models.billing import Product; db=SessionLocal(); p=db.query(Product).filter(Product.code=='modules_4_5').one(); print(p.code, p.display_name, p.price_cents, p.stripe_price_id)"
You should see one line ending with the price_ ID you pasted into Railway. Type exit to leave the shell.

Batch D — Tell Stripe where to send the “paid” signal, and start a worker

Why: After the user pays on Stripe, Stripe must tell Mynaani. Mynaani then needs a worker to add the purchase to the learner's account.

D1. Add the webhook endpoint in Stripe

  1. In Stripe, click “Developers” in the left sidebar.
  2. Click “Webhooks”.
  3. Click the “+ Add endpoint” button.
  4. In the box called “Endpoint URL”, paste exactly:
    https://noni-api-production.up.railway.app/api/v1/billing/stripe-webhook
  5. Click the box called “Select events”.
  6. Check these two events:
    • checkout.session.completed
    • charge.refunded
  7. Click “Add endpoint”.
  8. You will be taken to the new endpoint’s detail page. Look for “Signing secret” and a value starting with whsec_. Click “Reveal”, then copy it. Label it “Stripe webhook secret”.

D2. Put the webhook secret into Railway and turn Stripe on

  1. Go back to the Railway project, noni-api service, “Variables” tab.
  2. Find the empty STRIPE_WEBHOOK_SECRET variable. Click the pencil.
  3. Paste the whsec_ secret. Save.
  4. Now flip the switch: find PAYMENT_PROVIDER, click the pencil, change mock to stripe, and save.
  5. Click the “Deploys” tab and click “Redeploy” (or the three dots on the latest deploy → “Redeploy”). Wait for the green checkmark.
Check your work: Open a terminal and run:
curl https://noni-api-production.up.railway.app/api/v1/billing/health
It should say: {"provider":"stripe","stripe_mode":"live"}.
If you see an error instead, check that both STRIPE_SECRET_KEY and STRIPE_WEBHOOK_SECRET are filled in, then redeploy again.

D3. Add Redis so the worker can do its job

  1. In Railway, click “New” in the top right (or the “+” button in the project).
  2. Choose “Database” or “Template” and search for “Redis”.
  3. Create the Redis service. Railway will fill in the REDIS_URL variable for you.
  4. Make sure the noni-api service now has a variable called REDIS_URL and it looks like redis://.... If not, click the three dots on the Redis service and choose “Variables”, then copy the connection string and paste it as REDIS_URL in the noni-api service.

D4. Start the Celery worker

Choose one of these two ways. Ask an engineer if you are not sure which one to use.

Option 1 — Add a worker service:
  1. In Railway, click “New” → “Empty project” or “GitHub Repo” and choose the same repo.
  2. Click the service, open “Settings”, and set the “Start Command” to:
    celery -A backend.tasks.celery_app worker --loglevel=info
  3. Make sure the worker service has the same environment variables as noni-api (especially DATABASE_URL and REDIS_URL).
Option 2 — Add a worker start command to the same service:
  1. In noni-api “Settings”, look for “Start Command”.
  2. Change it to run both the web server and the worker. This is harder and is best done by an engineer.

Batch E — Make the website talk to the right backend

Why: When the user pays and comes back to www.mynaani.com, the browser must point to the live Railway backend, not the old Fly or Pages preview URL.

E1. Update the API base URL for Cloudflare Pages

  1. Go to the GitHub repo: github.com/smiles70/Noni.
  2. Click “Settings” at the top, then “Secrets and variables” → “Actions”.
  3. Find the variable called VITE_API_BASE_URL. Click the pencil.
  4. Make sure the value is:
    https://noni-api-production.up.railway.app
  5. Save and wait for the next Cloudflare Pages build, or go to “Actions” and run the Deploy workflow.

E2. Update CORS in Railway

  1. In Railway, go to the noni-api “Variables” tab.
  2. Find or add CORS_ORIGINS.
  3. Paste:
    https://mynaani.com,https://www.mynaani.com
  4. Redeploy.

E3. Check the custom domain (if it is already set up, just verify)

  1. Go to Cloudflare dashboard.
  2. Open the noni-web Pages project.
  3. Click “Custom domains” (or “Domains”).
  4. You should see www.mynaani.com with a green check. If not, the domain is not ready yet; ask the person who set up DNS.
  5. Check that mynaani.com forwards to https://www.mynaani.com in GoDaddy.

Batch F — Test with real money (or a real card you control)

Why: You must prove the whole path works before real customers see it.

F1. Test a self-purchase

  1. Open https://www.mynaani.com in a private or incognito browser window.
  2. Sign in with a test email.
  3. Go to the paywall (the screen that appears before Module 4).
  4. Click “Continue and purchase for myself”.
  5. You should be taken to a Stripe checkout page.
  6. Use a real card that you control. Pay.
  7. You should land on https://www.mynaani.com/purchase/success?cs=.... Note: the success page may not show the product name in live mode — that is a known cosmetic issue. What matters is the next step.
  8. Go back to the curriculum. Within about 30 seconds the paywall should be gone. If it is still there after 2 minutes, the webhook or worker is not working — check the Railway worker logs and the Stripe dashboard under Developers → Webhooks → your endpoint → “Event deliveries”.

F2. Test a gift purchase — currently blocked

Do not test gifts with real money yet. There is a known bug: in live Stripe mode, the gift code is lost when Stripe sends the buyer back to the site. The buyer pays but never sees the code. Engineering must fix this first (it is tracked as defect D1 in the intake document). Only test gifts after an engineer confirms the fix is deployed. The steps below are for after the fix.
  1. Go to the paywall again with a different test account (the buyer).
  2. Click “Buy as a gift for someone else”.
  3. Pay with a real card.
  4. Copy the gift code shown on the success page.
  5. Sign out, then sign in with a third account (the recipient).
  6. Go to the paywall, click “I have a gift code to redeem”, and paste the code.
  7. The recipient should now have access to Modules 4-5.

F3. Test a refund

  1. In the Stripe dashboard, click “Payments”.
  2. Find the test payment you just made.
  3. Click the payment, then click “Refund”.
  4. Back in Mynaani, the account that bought the product should no longer see Modules 4-5.
Clean up after testing: If you used a real card, refund every test purchase in the Stripe dashboard so you are not accidentally charged.
