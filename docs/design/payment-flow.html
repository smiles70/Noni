Refund Flow — Target (Stripe)

flowchart LR
    D[Stripe dashboard] -->|Merchant refunds| ST[Stripe sends charge.refunded]
    ST -->|Webhook| WH[POST /api/v1/billing/stripe-webhook]
    WH --> Q[Enqueue Celery task]
    Q --> W[process_stripe_webhook]
    W --> EV[process_event]
    EV --> DB[Mark purchase refunded + revoke entitlement]

Key changes moving from mock to Stripe:
  • Checkout happens on checkout.stripe.com, not a fake local page.
  • Success page no longer calls mock-checkout-complete; access is granted by the Stripe webhook.
  • A Celery worker backed by Redis is required to process webhooks.
  • Refunds are initiated in the Stripe dashboard and trigger entitlement revocation via webhook.
